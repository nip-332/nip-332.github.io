NIP-332

assumeUTXO Attestations over Nostr
Latest Attestations How It Works Example Subscribe Specification GitHub

Who verified this snapshot? An assumeUTXO snapshot is a UTXO set at a block, identified by its hash. Today a node trusts only the hashes compiled into its own software, and the record of who else checked them is scattered across review threads. NIP-332 defines a single regular Nostr event (kind 3332) in which a node says, under its own key, that it computed the hash itself or loaded the snapshot and validated the chain behind it. Free to make, permanent once made: a wrong attestation stays visible, so a key's history is its reputation.

How It Works

  • A statement, not a vote: the content is a canonical JSON statement with a subject (the block, the set's hash and its hash function, the same for every attester) and a claim (what this node did: recomputed from blocks, or loaded and validated; where its own chainstate came from; which software). The facts are read from the node, never typed.
  • Permanent: a regular event, not a replaceable one. Relays keep every attestation. A correction is a new event that references the old; nothing is overwritten.
  • Weighed, not counted: a recomputation on a fully synced node is worth the most, a load with validation less, and a node whose chainstate came from a snapshot at or above the height has verified nothing. Counts never promote a hash; a disagreement is settled by recomputing.
  • Checkable: signature, canonical form, the rules of the claim, tags against content, and, with a node of that chain, that the block is on it. This page checks the first four in your browser before showing a row.

["REQ", "attestations", {
  "kinds": [3332],
  "#network": ["tbtc4"],
  "#height": ["150000"]
}]

Or by #txoutset_hash for one snapshot, or authors for everything a key has attested. See the full specification.
